# Reference: Database schema

The app uses a single **Cloudflare D1** database (SQLite), bound to Functions as
`DB`. The schema is defined in `migrations/0001_initial.sql`, seeded by
`migrations/0002_seed_challenges.sql`, and extended by
`migrations/0003_attribution_and_funnel.sql` (`sessions`, `events`, and the
attribution columns on `leads`), and `migrations/0004_share_referrals.sql`
(`sessions.shared_by`).

```
challenges ──1:N── challenge_translations
    │
    │ (key referenced by completions.challenges_seen JSON)
    ▼
completions ──N:1── leads
    │
    └──1:N── shares

sessions ┄┄ session_id ┄┄ completions · events · leads
```

Solid lines are declared foreign keys. Dotted lines are joins on `session_id`
with **no** declared foreign key: a `sessions` row is written by `/api/start`,
and `completions`, `events` and `leads` carry the same `session_id`. Every
funnel stage can therefore be broken down by the session's attribution.

## `challenges`

The content pool. One row per quiz challenge, language-independent.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | autoincrement |
| `key` | TEXT | **unique**, stable identifier (e.g. `fake_mygov_sms_01`) |
| `type` | TEXT | one of `spot_it`, `pick_stronger`, `scenario`, `real_ai` (CHECK) |
| `category` | TEXT | grouping label (e.g. `phishing`) |
| `difficulty` | INTEGER | 1–3 (CHECK), default 1 |
| `is_active` | INTEGER | `1` = served, `0` = retired. Default 1 |
| `image_path` | TEXT | optional asset path |
| `correct_answer` | TEXT | e.g. `scam` / `legit` / an option key |
| `metadata` | TEXT | JSON blob; shape varies by `type` |
| `source_note` | TEXT | attribution / provenance |
| `created_at` | TEXT | defaults to `CURRENT_TIMESTAMP` |

Indexed by `(is_active, type)` for the selection query.

> `key` is the join point used everywhere else — `completions.challenges_seen`
> and `completions.answers` store arrays of these keys, not foreign keys.

## `challenge_translations`

The translatable text for each challenge, one row per `(challenge, language)`.
The challenges API joins this table on `language_code`.

| Column | Type | Notes |
|---|---|---|
| `challenge_id` | INTEGER | part of composite PK; FK → `challenges(id)` `ON DELETE CASCADE` |
| `language_code` | TEXT | part of composite PK (e.g. `en`) |
| `prompt` | TEXT | the question text |
| `options` | TEXT | JSON array of options |
| `explanation` | TEXT | shown as feedback after answering |

Composite primary key: `(challenge_id, language_code)`.

## `leads`

Captured lead data (PII). Written only by `POST /api/lead` after Turnstile
verification.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | autoincrement |
| `first_name` | TEXT | required |
| `email` | TEXT | required |
| `phone` | TEXT | optional; not collected by the current form (older leads may have it) |
| `postcode` | TEXT | optional (4-digit AU); not collected by the current form |
| `language` | TEXT | default `en` (currently always `en` on insert) |
| `consent_program` | INTEGER | required; stored 1/0 |
| `consent_marketing` | INTEGER | default 0; the current form stores 0 |
| `utm_source` / `utm_medium` / `utm_campaign` | TEXT | optional attribution; lower-cased |
| `utm_content` | TEXT | optional; creative ID, stored verbatim. Added in `0003` |
| `referrer` | TEXT | optional; referring hostname only. Added in `0003` |
| `session_id` | TEXT | the quiz session the sign-up came from (no FK). Added in `0003`; `NULL` for older leads |
| `created_at` | TEXT | defaults to `CURRENT_TIMESTAMP` |

Indexed by `email`, `created_at` and `session_id`.

## `completions`

One row per finished challenge run. Anonymous unless later linked to a lead via
`lead_id`. `POST /api/complete` upserts by `session_id`.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | autoincrement |
| `session_id` | TEXT | **unique**; generated by `/api/challenges` |
| `lead_id` | INTEGER | nullable; FK → `leads(id)`. Set by `/api/lead` |
| `score` | INTEGER | required |
| `total` | INTEGER | required |
| `max_streak` | INTEGER | default 0 |
| `tier` | TEXT | computed server-side (`learner`/`aware`/`defender`/`champion`) |
| `duration_seconds` | INTEGER | nullable |
| `challenges_seen` | TEXT | JSON array of challenge keys |
| `answers` | TEXT | JSON array of `{ key, answer, correct, timeMs }` |
| `language` | TEXT | default `en` |
| `completed_at` | TEXT | defaults to `CURRENT_TIMESTAMP` |

Indexed by `session_id` and `lead_id`.

> A completion exists for **everyone who finishes all challenges**, whether or
> not they submit the sign-up form. The lead link is optional and added later. See
> [Explanation: Privacy and data](../explanation/privacy-and-data.md).

## `sessions`

One row per challenge **start** (funnel stage 1), with first-touch campaign
attribution. Written by `POST /api/start` (`INSERT OR IGNORE`). Anonymous — no
PII. A retake is a new session. Added in `0003`.

| Column | Type | Notes |
|---|---|---|
| `session_id` | TEXT PK | generated by `/api/challenges` |
| `utm_source` / `utm_medium` / `utm_campaign` | TEXT | optional; lower-cased |
| `utm_content` | TEXT | optional; creative ID, stored verbatim |
| `referrer` | TEXT | optional; referring hostname only |
| `embedded` | INTEGER | 1 if started inside the Squarespace iframe; default 0 |
| `language` | TEXT | default `en` |
| `started_at` | TEXT | defaults to `CURRENT_TIMESTAMP` |
| `shared_by` | TEXT | optional; `session_id` of the participant whose share link brought this visitor in (no FK). Added in `0004` |

Indexed by `started_at`, `(utm_source, utm_campaign)` and `shared_by`.

Sessions that came from a participant share also have `utm_medium = 'share'`,
`utm_campaign = 'participant_share'` and `utm_source` set to the share platform.

## `events`

Click-level funnel steps that have no table of their own. Written by
`POST /api/event`, only when a matching `sessions` row exists. Repeat clicks
create repeat rows. Added in `0003`.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | autoincrement |
| `session_id` | TEXT | required; joins to `sessions` (no FK) |
| `event_type` | TEXT | `course_cta_click` or `workshop_click` (CHECK) |
| `created_at` | TEXT | defaults to `CURRENT_TIMESTAMP` |

Indexed by `(session_id, event_type)`.

## `shares`

Analytics events: one row per share action.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | autoincrement |
| `completion_id` | INTEGER | FK → `completions(id)` |
| `platform` | TEXT | `facebook`/`whatsapp`/`linkedin`/`native`/`copy`/`twitter` (no CHECK; `linkedin` from `0004`) |
| `created_at` | TEXT | defaults to `CURRENT_TIMESTAMP` |

## Indexes (summary)

```sql
idx_leads_email            ON leads(email)
idx_leads_created          ON leads(created_at)
idx_leads_session          ON leads(session_id)              -- 0003
idx_completions_session    ON completions(session_id)
idx_completions_lead       ON completions(lead_id)
idx_challenges_active_type ON challenges(is_active, type)
idx_sessions_started       ON sessions(started_at)           -- 0003
idx_sessions_source        ON sessions(utm_source, utm_campaign)  -- 0003
idx_events_session_type    ON events(session_id, event_type) -- 0003
idx_sessions_shared_by     ON sessions(shared_by)            -- 0004
```

## Querying the database

Use wrangler with `--local` (dev) or `--remote` (production):

```sh
cd frontend
# count active challenges (local)
npx wrangler d1 execute cybersecurity-champions-db --local \
  --command="SELECT count(*) FROM challenges WHERE is_active=1;"

# recent leads (production), as JSON
npx wrangler d1 execute cybersecurity-champions-db --remote \
  --command="SELECT id, first_name, email, created_at FROM leads ORDER BY created_at DESC LIMIT 20;" --json
```

See [How-to: Export and manage leads](../how-to/export-and-manage-leads.md) and
[How-to: Manage challenges](../how-to/manage-challenges.md) for task recipes.
